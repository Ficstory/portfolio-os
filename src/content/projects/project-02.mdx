# Frontend Collaboration

## 문제 정의

프론트엔드 작업은 화면을 만드는 일뿐 아니라 요구사항을 해석하고, 컴포넌트 책임을 나누고, BE나 기획과 확인해야 할 내용을 분리하는 과정이 필요합니다. 이 프로젝트는 협업 과정에서 FE가 어떤 기준으로 정보를 정리하는지 보여주는 샘플 콘텐츠입니다.

## 내 역할

- 요구사항을 화면 단위와 데이터 단위로 나누어 정리합니다.
- UI에서 처리할 수 있는 범위와 BE 전달이 필요한 범위를 구분합니다.
- 변경 내역을 커밋과 MR 설명으로 추적할 수 있게 작업 내용을 요약합니다.

## 기술 스택

- React
- TypeScript
- Figma
- Git
- Markdown

## 주요 구현

작업 범위를 문서, 데이터, 컴포넌트 책임으로 나누어 정리하는 방식을 사용했습니다. 실제 BE 연동이 필요한 기능은 MVP 범위에서 제외하고, 추후 전달해야 할 항목으로 분리할 수 있도록 설명합니다.

## 트러블슈팅

요구사항이 불명확한 상태에서 임의로 화면을 확장하면 MVP 범위가 커질 수 있습니다. 따라서 확인되지 않은 블로그, 노트, CMS, 서버 저장형 기능은 제외하고 정적 콘텐츠 중심으로 제한했습니다.

## 성과

- FE 작업자가 다룰 범위와 협업 전달사항을 분리하는 예시를 마련했습니다.
- 실제 협업 사례가 생기면 역할과 결과를 구체적인 내용으로 대체할 수 있습니다.
- MVP에서 BE 작업이 필요하지 않다는 전제를 콘텐츠에도 반영했습니다.

## 링크

공개 가능한 링크는 아직 연결하지 않았습니다.
