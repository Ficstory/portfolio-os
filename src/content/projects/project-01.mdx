# Portfolio OS

## 문제 정의

개인 포트폴리오가 단순 소개 페이지에 머물지 않고, 프로젝트와 기술 경험을 탐색 가능한 구조로 보여줄 필요가 있었습니다. MVP에서는 실제 이력 데이터가 충분하지 않기 때문에 과장된 성과보다 화면이 사용할 수 있는 안전한 샘플 콘텐츠를 먼저 준비합니다.

## 내 역할

- About, Projects, Skills, Resume, Contact에 필요한 정적 데이터 구조를 정리합니다.
- 대표 프로젝트를 3개로 제한하고 같은 필드 구조를 사용하도록 맞춥니다.
- UI 컴포넌트가 링크가 없는 경우 숨길 수 있도록 링크 데이터를 빈 객체로 둡니다.

## 기술 스택

- Next.js
- React
- TypeScript
- Tailwind CSS
- Zustand

## 주요 구현

프로젝트 목록과 상세 화면이 함께 사용할 수 있도록 `id`, `slug`, `summary`, `role`, `stack`, `implementationHighlights`, `troubleshooting`, `result`, `links` 필드를 동일하게 구성했습니다. 실제 이미지나 외부 링크가 없는 항목은 빈 문자열 또는 빈 배열로 두어 UI에서 조건부 렌더링할 수 있게 합니다.

## 트러블슈팅

실제 프로젝트 성과가 없는 상태에서 수치나 결과를 임의로 만들면 포트폴리오의 신뢰도가 떨어질 수 있습니다. 따라서 성과 영역은 MVP 데이터 구조 마련, 향후 실제 정보로 교체 가능하다는 확인 가능한 범위로만 작성했습니다.

## 성과

- MVP 화면 구현에 필요한 프로젝트 데이터 구조를 준비했습니다.
- 상세 콘텐츠가 같은 순서의 섹션을 갖도록 기준을 만들었습니다.
- 실제 이력 정보가 확정되면 같은 구조 안에서 내용을 교체할 수 있습니다.

## 링크

공개 가능한 링크는 아직 연결하지 않았습니다.
