# Problem Solving Archive

## 문제 정의

트러블슈팅 경험은 시간이 지나면 문제의 원인과 해결 이유가 흐려지기 쉽습니다. MVP에서는 별도의 블로그나 노트 기능을 만들지 않고, 프로젝트 상세 콘텐츠 안에서 문제 해결 과정을 일정한 순서로 기록합니다.

## 내 역할

- 문제 정의, 시도, 해결, 배운 점을 프로젝트 상세 구조 안에 배치합니다.
- 실제 성과가 확인되지 않은 항목은 정량 수치로 표현하지 않습니다.
- 향후 실제 사례를 추가할 수 있도록 MDX 콘텐츠의 섹션 순서를 통일합니다.

## 기술 스택

- TypeScript
- MDX
- Markdown
- ESLint
- Next.js

## 주요 구현

상세 콘텐츠의 섹션을 문제 정의, 내 역할, 기술 스택, 주요 구현, 트러블슈팅, 성과, 링크 순서로 고정했습니다. 이 구조는 프로젝트마다 같은 방식으로 읽히며, UI가 MDX 콘텐츠를 연결할 때도 예측 가능한 흐름을 제공합니다.

## 트러블슈팅

문제 해결 아카이브가 블로그 기능처럼 확장되면 MVP 범위를 벗어날 수 있습니다. 그래서 내부 노트나 블로그 글을 만들지 않고 대표 프로젝트 상세 설명 안에서만 문제 해결 맥락을 다루도록 제한했습니다.

## 성과

- 프로젝트 상세 콘텐츠가 같은 순서와 밀도를 갖도록 기준을 만들었습니다.
- 확인되지 않은 성과를 과장하지 않고, 실제 자료가 생기면 교체 가능한 형태로 작성했습니다.
- 이후 트러블슈팅 사례를 추가할 때 재사용할 수 있는 템플릿을 확보했습니다.

## 링크

공개 가능한 링크는 아직 연결하지 않았습니다.
