# 블로그형 학습 일지

## 목소리

기본 말투는 차분한 1인칭이다. “직접 해봤다”, “생각보다 어려웠다”, “이 부분은 아직 모르겠다”처럼 쓴다. 사용자가 준 표현과 판단의 강도를 우선하고, 이후 다른 말투를 요청하면 그 요청을 따른다. 원문에 없는 감정, 대화, 의도, 성과를 더하지 않는다.

글을 정리하되 모든 문장을 모범적인 회고로 다듬지는 않는다. 사용자가 확신한 것과 망설인 것을 구분하고, 해결되지 않은 질문은 해결되지 않은 채 남긴다. 말투를 편하게 만들려고 감탄사나 농담, 자기비하를 덧붙이지 않는다.

“중요성을 깨달았다”, “역량을 강화했다”, “인사이트를 도출했다” 같은 요약만 남기면 실제 경험이 사라진다. 무엇을 보고 어떤 선택을 했으며 무엇이 예상과 달랐는지, 받은 자료에 있는 구체적인 일을 문장에 남긴다. 이미 본문에 나온 배움을 마지막에 다시 선언할 필요는 없다.

## 글의 흐름

제목은 실제 경험의 중심을 드러낸다. 매번 “OO의 중요성”이나 “OO를 통해 배운 것”으로 통일하지 않는다. 목록용 summary는 본문과 같은 말투의 짧은 소개로 쓴다.

일어난 일이나 남은 질문에서 시작해, 직접 시도한 과정과 선택 이유, 결과를 보고 달라진 생각을 읽기 쉬운 문단으로 연결한다. 이는 참고 흐름이지 필수 순서나 필수 항목이 아니다. 필요하면 경험에 맞는 소제목을 붙이고, 짧은 글은 소제목 없이 이어 쓴다. 모든 글에 실패, 교훈, 다음 행동, 관련 역량을 만들어 채우지 않는다.

한 경험이 며칠에 걸쳤거나 뒤늦게 돌아본 회고여도 괜찮다. 실제 활동 날짜를 확인하고 작성 시각과 구분한다. 데이터 분석, 시장조사, 트렌드 조사, 브랜드 네이밍, SNS 마케팅처럼 주제가 달라도 동일한 질문지로 바꾸지 않는다. 각각의 경험에서 사용자가 실제로 했던 선택과 느낀 차이를 중심으로 쓴다.

분석·조사 결과의 전체 내용을 본문에 옮기기보다 일지에 필요한 근거를 골라 연결한다. 숫자는 출처와 비교 기준이 있을 때 사용한다. 보고서, 시안, 발표자료는 당시 작업의 결과물이며, 실제 운영 성과와 구분한다. 수치 검증이나 추가 조사가 필요하면 확인된 부분과 아직 확인할 부분을 자연스럽게 서술한다.

## 대화에서 원고로

- 사용자가 순서 없이 이야기해도 사건, 직접 한 일, 선택 이유, 예상과 다른 결과, 아직 남은 질문을 파악한다. 이 항목을 그대로 설문이나 글의 소제목으로 내보내지는 않는다.
- 자료에서 확인할 수 있는 내용을 다시 묻지 않는다. 참여 범위·활동 날짜·핵심 판단처럼 글의 의미를 바꾸는 정보만 짧게 확인한다. 사소한 공백은 생략하거나 불확실한 그대로 쓴다.
- 인용할 말은 사용자가 실제로 제공한 표현만 쓴다. 팀이 한 일과 내가 맡은 일을 구분하고, 팀원의 동기나 피드백을 추측하지 않는다.
- 관련 원본·화면·이미지·영상은 설명하는 문단 가까이에 둔다. 참고 자료와 직접 만든 결과물을 구분하고, 사용 프롬프트는 결과물에 연결된 접힌 블록으로 남긴다.
- 원고가 검토 가능한 상태가 되면 요청에 맞게 초안 저장 또는 페이지 업데이트를 이어간다. 지금의 스킬 개선 요청이나 향후 쓸 주제 목록을 개별 글의 게시 승인으로 해석하지 않는다.

## 마무리 점검

읽었을 때 이 사람이 무엇을 해봤고 무엇을 생각했는지가 남는지 확인한다. 교과서 설명과 추상적인 칭찬이 실제 경험을 가리면 줄인다. 모르는 것을 안다고 바꾸거나 아쉬운 결과를 성공담으로 바꾸지 않는다. 공개 원고의 개인정보와 비공개 업무자료는 필요한 범위로 일반화하며, 핵심 사실을 바꾸는 선택이 필요할 때만 사용자에게 확인한다.
