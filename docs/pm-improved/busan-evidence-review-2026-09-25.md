- 기존 사용자 확인 기록과 코드/문서 이력: 초기 기획, 함세상 기관 섭외·4월 10일 인터뷰, MVP 결정, 지도 마커·카메라 동기화, 글자 크기 저장·적용, 승인 제보 표시와 상세 패널, 명세 관리.

## 역할과 주장 범위

- 개인 기여는 기존 사용자 확인과 커밋 기록으로 확인되는 범위로 유지한다.
- 경로 알고리즘, 공간 데이터, 저시력 모드, 일반 제보 등록, 즐겨찾기, 관리자·모니터링 전체 개발은 개인 성과로 확대하지 않는다.
- 관리자 화면의 구체적인 개인 담당 여부는 추가 확인 전까지 팀 결과로 표기한다.
- 기존 README와 6월 신청서의 팀장 표기가 서로 달라, 프로젝트 전체 기간의 총괄 팀장이라는 새 주장을 추가하지 않는다.
- 신청서에는 4월 10일과 5월 18일의 기관 방문 기록이 있다. 개인 MVP 근거인 4월 인터뷰와 프로젝트 전체의 기관 접촉 범위를 혼동하지 않는다.
- 실제 출시 후 이용률, 경로 안전성, 이동시간 단축, 사용자 검증 성공 등의 정량 성과는 확인 자료가 없어 기재하지 않는다.

## 공개용 미디어 처리

- 관리자 캡처는 원본 비율을 유지하고 확대 링크를 제공한다.
- 영상은 무음 공개용 사본으로 제공하고 선택한 기능 한 개만 로드한다. 자동 재생하지 않는다.
- 제보 영상은 사진 선택 화면에 우발적으로 노출되는 개인 사진을 피하도록 원본 0~15.20초를 발췌했다. 완료·승인까지 보여주는 영상으로 설명하지 않는다.
- 약정서/신청서 원본 및 개인 연락처, 서명, 주소 등은 public 경로에 추가하지 않는다.

## 있으면 더 강해지는 후속 자료

현재 자료로 구현 사례 페이지는 완성할 수 있다. 아래는 향후 결과 주장을 강화할 때 필요한 별도 근거다.

1. 실제 보행약자 테스트 기록: 참여 조건, 수행 과제, 관찰 문제, 수정 전후. 개인정보 및 동의 범위를 확인한 요약본.
2. 경로/지도 사용성 측정: 탐색 성공률, 과제 시간, 오류 사례 등 측정 조건을 함께 설명할 수 있는 데이터.
3. 관리자 기능에서 본인이 맡은 기획·개발 범위가 있다면 이를 확인할 담당 기록/커밋.
4. API 연동 기여를 더 구체화하려면 개인정보를 제거한 협의 기록·검수 체크리스트·본인 구현 내역.

추가 자료가 없다는 이유로 검증되지 않은 성과를 만들어 넣지 않는다.
