# 2026-06-04 페이지 로딩 및 시간 동기화 지연 트러블슈팅

## 1. 문제 현상

루트 페이지(`/`) 진입 시 잠금 화면이 표시되기까지 체감 로딩이 느리고, 잠금 화면의 현재 시간과 시간대별 배경이 실제 시각에 맞춰지는 데 약 5초 정도 걸리는 것처럼 보였다.

사용자가 체감한 문제는 두 가지였다.

- 첫 화면 표시가 무겁다.
- 시간 동기화가 늦게 되는 것처럼 보인다.

이 문제는 `docs/01_requirements_spec.md`의 `NFR-001`인 "첫 로딩은 빠르게 유지하고 불필요한 대형 라이브러리를 피한다"와 직접 연결된다.

## 2. 조사 범위

초기에는 시간 동기화 API나 네트워크 지연 가능성을 의심했지만, 코드 검색 결과 외부 시간 API 호출은 없었다.

확인한 주요 파일은 다음과 같다.

- `src/app/page.tsx`
- `src/app/layout.tsx`
- `src/lib/useMinuteClock.ts`
- `src/lib/timeTheme.ts`
- `src/components/desktop/DesktopShell.tsx`
- `src/components/desktop/Dock.tsx`
- `src/components/desktop/WindowManager.tsx`
- `src/components/lock-screen/LockScreen.tsx`
- `public/images/wallpapers/*`

확인 명령은 다음과 같다.

```bash
rg -n "time|시간|sync|Date|now|setInterval|fetch|api|clock|loading|dynamic" src public
npm.cmd run build
Get-ChildItem -Path "public" -Recurse -File | Sort-Object Length -Descending
Get-ChildItem -Path ".next\server\app\index.html",".next\server\app\index.rsc"
```

## 3. 원인

### 3.1 잠금 화면 뒤에 데스크톱 전체가 함께 렌더링됨

`src/app/page.tsx`는 잠금 화면 상태에서도 `DesktopShell`을 항상 렌더링하고 있었다.

```tsx
<DesktopShell isVisible={isDesktopVisible} now={now} resolvedTheme={resolvedTheme} />
```

`isVisible=false`일 때 화면에는 보이지 않지만, React 트리와 정적 HTML에는 데스크톱 UI가 포함됐다. 그 결과 잠금 화면만 보여야 하는 첫 진입 시점에도 아래 컴포넌트들이 함께 준비됐다.

- `MobileHome`
- `MenuBar`
- `Dock`
- `WindowManager`
- 폴더/프로젝트 상세 콘텐츠 일부
- `motion/react`
- `next/image`
- dock icon 이미지 처리 코드

production build 기준 루트 페이지의 `index.html`은 약 `101,279B`였다. HTML 안에 숨겨진 모바일 문서와 데스크톱 dock 마크업까지 포함되어 있었다.

### 3.2 시간 동기화 지연처럼 보이는 원인은 hydration 전 정적 시간

`src/lib/useMinuteClock.ts`는 외부 시간 서버와 동기화하지 않는다. 로컬 `new Date()`를 사용하고, 1초마다 확인하되 분이 바뀔 때만 상태를 갱신한다.

```ts
const [now, setNow] = useState(() => new Date());
```

문제는 Next.js 정적 prerender 결과에 빌드 시점의 시간이 먼저 들어간다는 점이었다. 사용자는 React hydration이 끝나기 전까지 정적 HTML에 박힌 시간을 보게 되고, 이 구간이 길면 "시간 동기화가 오래 걸린다"고 느끼게 된다.

즉, 실제 병목은 시간 API가 아니라 초기 hydration 전 화면 보정이 늦는 구조였다.

### 3.3 배경 PNG가 첫 화면 대비 과하게 큼

시간대별 배경 PNG 파일 크기는 다음과 같았다.

| 파일 | 기존 크기 |
| --- | ---: |
| `dawn.png` | 1,626,211B |
| `day.png` | 1,826,717B |
| `evening.png` | 1,503,604B |
| `night.png` | 2,342,590B |

첫 화면 배경은 반드시 필요한 자산이지만, 1.5~2.3MB PNG를 그대로 쓰는 것은 초기 로딩에 부담이 컸다.

## 4. 해결 내용

### 4.1 데스크톱 셸을 unlock 이후 lazy load

`DesktopShell`과 `PortfolioTrackProvider`를 루트 페이지에서 직접 import하지 않고, `PortfolioDesktopShell`로 분리한 뒤 `next/dynamic`으로 지연 로드했다.

수정 파일:

- `src/components/portfolio/PortfolioDesktopShell.tsx`
- `src/app/page.tsx`

핵심 변경:

```tsx
const PortfolioDesktopShell = dynamic(
  () =>
    import("@/components/portfolio/PortfolioDesktopShell").then(
      (module) => module.PortfolioDesktopShell,
    ),
  {
    loading: () => null,
    ssr: false,
  },
);
```

그리고 unlock 전에는 데스크톱 컴포넌트를 렌더링하지 않도록 변경했다.

```tsx
{isDesktopVisible ? (
  <PortfolioDesktopShell
    isVisible={isDesktopVisible}
    now={now}
    resolvedTheme={resolvedTheme}
  />
) : null}
```

이렇게 해서 잠금 화면 초기 진입 시점에는 desktop, mobile document, dock, window manager, `motion/react`, `next/image` 계열 코드가 첫 HTML에서 빠졌다.

### 4.2 hydration 전 시간과 배경을 즉시 보정

`src/app/layout.tsx`에 작은 inline script를 추가했다.

스크립트 역할은 다음과 같다.

- 현재 로컬 시간 계산
- `data-time-theme` 보정
- `data-theme` 보정
- 시간대별 배경 이미지 보정
- 잠금 화면의 시간/날짜 텍스트 보정

대상 DOM을 안정적으로 찾기 위해 다음 속성을 추가했다.

- `data-portfolio-root`
- `data-wallpaper-layer`
- `data-live-clock="time"`
- `data-live-clock="date"`

이 변경으로 React hydration이 끝나기 전에도 화면에 표시되는 시간과 배경이 현재 로컬 시간 기준으로 즉시 맞춰진다.

### 4.3 배경 이미지를 WebP로 최적화

`sharp`를 사용해 시간대별 배경을 WebP로 변환했다.

생성 파일:

- `public/images/wallpapers/dawn.webp`
- `public/images/wallpapers/day.webp`
- `public/images/wallpapers/evening.webp`
- `public/images/wallpapers/night.webp`

`src/lib/timeTheme.ts`와 `src/app/layout.tsx`의 배경 경로도 `.webp`로 변경했다.

변환 결과:

| 배경 | PNG | WebP |
| --- | ---: | ---: |
| dawn | 1,626,211B | 42,962B |
| day | 1,826,717B | 69,218B |
| evening | 1,503,604B | 30,914B |
| night | 2,342,590B | 125,442B |

가장 큰 `night` 기준으로도 약 2.34MB에서 125KB 수준으로 줄었다.

## 7. 재발 방지 기준

앞으로 루트 잠금 화면을 수정할 때는 다음 기준을 지킨다.

- 잠금 화면 뒤에 숨겨진 대형 UI를 SSR/초기 HTML에 넣지 않는다.
- `opacity: 0`, `pointer-events-none`만으로 초기 렌더 비용을 숨기지 않는다.
- 첫 화면에 필요한 이미지 자산은 가능하면 150KB 이하로 유지한다.
- 정적 HTML에 시간처럼 빠르게 변하는 값을 표시할 때는 hydration 전 보정 전략을 둔다.
- 시간대별 배경 경로를 변경할 때는 `timeTheme.ts`와 `layout.tsx`의 선행 보정 스크립트를 함께 갱신한다.
- 성능 개선은 체감만 보지 않고 `index.html`, 초기 청크, 이미지 크기 숫자로 확인한다.

## 8. 남은 개선 여지

현재 구조는 실사용 체감 개선에는 충분하지만, 더 줄이려면 다음 작업을 검토할 수 있다.

- `lucide-react` 아이콘 import를 더 잘게 분리해 초기 잠금 화면 청크 축소
- 잠금 화면 전용 컴포넌트를 더 작은 client island로 분리
- inline script의 시간대/배경 매핑을 중복 관리하지 않도록 빌드 타임 생성 방식 검토
- 실제 배포 URL에서 Lighthouse 또는 Web Vitals로 FCP/LCP 수치 측정
