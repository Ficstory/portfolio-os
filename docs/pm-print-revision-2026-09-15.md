## 소개 장표의 캡처 2장 배치

추가 요청에 따라 애낌(5장)과 부산이음길(2장)의 소개 장표에 캡처를 각각 두 장씩 나란히 배치했다. 두 이미지 모두 기존 104mm 높이를 유지하며, 각 48mm 폭과 6mm 사이 간격을 사용한다. 소개 문구와 이미지를 나누는 열 비율·간격만 인쇄 범위에서 조정했다.

- 애낌: GitHub README의 구독 통합 관리 + 프로모션 상세 원본. 기여 장표의 후보 확인·제외 이미지는 유지했다.
- 부산이음길: 시설 탐색 지도 + 사용자 유형 선택. 두 번째는 기존 `public/pm/busan-low-vision.png`(720×1560)를 재사용한다. 저시력자·보행약자 유형을 고르는 팀 서비스 화면으로, 개인 구현 전체를 증명하는 자료로 표시하지 않는다.

부산 추가 캡처의 출처는 `public/pm/sources/busan-readme.txt`와 `docs/pm-redesign/README.md`에 기록된 원본 `Docs/media/low-vision.mp4`다. 정확한 프레임 시각은 문서화되어 있지 않아 표시하지 않았다. 원본 PNG SHA-256은 `845bd7192e78ae8f176890f5479ee5dd156e2c8e1bf11c7dbd1caa5846ea944c`다.

## 프로세스 사실과 표현 기준

- 개발 방식과 회고는 2026-09-15 사용자가 직접 제공한 경험을 반영했다. 부산이음길은 애자일 방식에서 바뀐 구현 기준을 요구사항·화면명세에 반영했고, 문서를 최신 상태로 유지하는 일이 협업에 중요했다는 설명이다.
- 애낌은 워터폴 방식으로 진행했다. 중간 팀원 이탈, MVP 범위 변경, 예상보다 느린 개발을 겪고 다음 프로젝트에서는 범위와 구현을 더 자주 점검하는 방식으로 바꿔야겠다고 느꼈다는 회고다. 후속 프로젝트의 성과 향상 수치를 주장하지 않는다.
- 부산이음길의 현장 사진 캡션은 기관명·날짜를 검증 가능한 근거 없이 연결하지 않고 일반적인 미팅 사진으로 표기한다.

## 부산 문서 이력 증거

[Git 집계 자료](./pm-print/busan-doc-commits.json)와 [재현 스크립트](./pm-print/generate-busan-doc-commits.mjs)를 보관했다. 원본 저장소의 모든 로컬 참조에서 저자 이름이 정확히 `LeeJaeho` 또는 `이재호`인 비병합 커밋을 조회했다. 저자 일시가 `2026-04-01T00:00:00+09:00` 이상, `2026-06-01T00:00:00+09:00` 미만이고 루트 `Docs/` 경로를 변경한 고유 커밋은 **29건**이다(`LeeJaeho` 13건, `이재호` 16건). `FE/docs`만 수정한 커밋은 포함하지 않는다.

원본 저장소 HEAD는 `a4d140276d87afae163e8997685f66983f15eefc`다. 자료에는 전체 해시, 실제 저자/커미터 일시, 커밋 제목, 변경 경로, 조회한 참조를 기록했다. 원본 저장소는 수정하지 않았다. 장표에는 개인 기여임을 분명히 하기 위해 **“본인 문서 변경 커밋 29건”**, 범위에는 **“2026.04~05 · 기획·명세 등 Docs/ 기준 · 병합 제외”**를 표시했다. 이 집계가 공식 스크럼 운영이나 문서 품질 향상을 독립적으로 증명하는 것은 아니다.

## 수용 기준과 검증 상태

- 인쇄본은 정확히 13장이고, 순서는 1 표지, 2~4 부산이음길, 5~7 애낌, 8~10 웃지마게임, 11~12 Play Pick, 13 마무리다.
- 애낌 개요와 기여 장표는 위 표의 각 실제 앱 캡처를 사용하며, 캡처 한계를 캡션 또는 주변 문구로 유지한다.
- 일반 `/PM/` 웹 화면의 콘텐츠·접근성·스타일은 변경하지 않는다.
- 부산 사진은 검증되지 않은 기관명 또는 날짜를 사실처럼 캡션에 쓰지 않는다.
- 최종 production 빌드/TypeScript 및 변경 파일 ESLint 통과. 두 캡처 배치까지 반영한 Edge 153.0.4234.32와 Chrome 154.0.8037.17에서 각각 **174개 검사 통과**. 진단용 생략 옵션은 사용하지 않았다.
- `/PM/`와 `/PM/print/`에서 각각 13장 전체 PDF를 생성했다. 실제 PDF는 320×180mm이며, 한국어 본문을 검색할 수 있다. 26개 페이지를 PNG로 렌더링한 결과 두 경로의 페이지별 텍스트와 픽셀이 일치했다.
- 13장 전체를 육안 검수했다. 수정된 부산·애낌 문구와 이미지가 내용에 맞고 제목·본문·캡션·쪽 번호가 겹치거나 잘리지 않는다. 최소 본문/푸터 간격은 10.52 CSS px, 부산 추가 기여 장표는 28.77px다. 검사 본문 글자 크기는 12pt 이상이다.
- 일반 홈의 데스크톱/모바일 본문과 치수는 기존 기준과 일치한다. 기존 회귀 검사는 보호 파일 168개 해시, 경로 13개, 로컬 대상 70개 및 RSC·대소문자 경로 처리를 통과했다.
- Poppler의 일부 Type 3 글리프 경고는 기존 출력과 같다. 시각적 깨짐은 없으며, 일부 숫자의 복사·추출은 폰트 내부 글리프 코드로 반환될 수 있다. 한국어 본문 추출에는 문제가 없다.

최초 PDF 검수 원본은 `output/pdf/qa/dom-report.json`, `chrome-dom-report.json`, `pdf-report.json`, `web-regression.json` 및 페이지 PNG에 보관했다. 실제 OS 인쇄 대화상자 조작·물리 프린터·Safari/Firefox는 이번 검증에 포함하지 않았다.

## 최종 제출본 후속 수정

- 사용자 요청에 따라 교육 정보에서 `평점 3.74/4.5`를 삭제했다. 학교·학과·졸업 시점·학위는 유지한다. 1~12장의 텍스트와 원본 이미지가 이전 PDF와 동일함을 확인했다.
- 최신 원본 `output/pdf/lee-jaeho-pm-portfolio-preview.pdf`는 8,253,800바이트다. 이미지 압축과 중복 객체 정리로 만든 1.68MB 사본도 업로드 제한에 걸려 추가 최적화했다.
- 최종 제출 파일은 `output/pdf/lee-jaeho-pm-portfolio-under-1mb.pdf`, **905,012바이트**다. pikepdf의 객체 스트림 압축을 적용했으며, 직전 이미지 압축본 대비 13장 전체 렌더링 픽셀이 동일하다. 원본 대비 본문 텍스트·링크 URI와 좌표·페이지 크기도 동일하다.
- 사용자가 이 파일의 제출 성공을 확인했다. 생성된 PDF와 임시 압축 도구는 로컬 산출물이며 웹 페이지는 공용 인쇄 컴포넌트에서 렌더링한다.
- 배포는 GitHub `main`에 연결된 Vercel을 사용한다. README에 남아 있는 OCI 정적 업로드 안내는 현재 배포 설정과 다르다.
