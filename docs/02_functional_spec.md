# 기능 명세서

## 1. 기능 개요

MVP는 잠금화면형 랜딩에서 데스크톱 포트폴리오로 진입하는 구조다. 방문자는 바탕화면 아이콘, Dock, 창 UI를 통해 자기소개, 프로젝트, 기술, 이력서, 연락처를 탐색한다.

## 2. 화면 흐름

```txt
Lock Screen Landing
  -> Unlock Transition
  -> Desktop Workspace
  -> Folder Window
  -> Content Detail
```

## 4. 상세 기능 명세

### FEAT-001 잠금화면 랜딩

- 목적: 첫 화면에서 포트폴리오의 감성적인 OS 콘셉트를 전달한다.
- 표시 요소:
  - 현재 시간
  - 현재 날짜
  - 이름 또는 포트폴리오 주인 식별 문구
  - 짧은 자기소개 문장
  - `포트폴리오 입장` 버튼
  - GitHub, Resume, Email 빠른 링크
- 동작:
  - 방문 시 기본 진입 화면으로 표시된다.
  - 버튼 클릭 또는 Enter 키 입력으로 `FEAT-002`가 실행된다.
- 상태:
  - 기본 상태
  - hover/focus 상태
  - unlock 진행 상태

### FEAT-002 포트폴리오 입장 전환

- 목적: 잠금화면에서 데스크톱으로 들어가는 명확한 장면 전환을 제공한다.
- 동작:
  - 버튼 클릭 시 잠금화면 요소가 fade out 또는 scale out 된다.
  - 데스크톱 배경과 UI가 순차적으로 등장한다.
  - reduced motion 설정이 활성화된 경우 opacity 전환만 사용한다.
- 완료 조건:
  - 데스크톱 워크스페이스가 표시된다.
  - 첫 focus는 Desktop 또는 첫 번째 폴더 아이콘으로 이동한다.

### FEAT-003 데스크톱 워크스페이스

- 목적: 포트폴리오 콘텐츠를 폴더 기반 탐색 구조로 제공한다.
- 표시 요소:
  - 배경 wallpaper
  - Menu Bar
  - DesktopIconGrid
  - Dock
  - WindowLayer
- 기본 폴더:
  - About Me
  - Projects
  - Skills
  - Resume
  - Contact
- 2차 기능 폴더:
  - Notes 또는 Blog

### FEAT-004 바탕화면 폴더 실행

- 목적: 사용자가 폴더를 열어 콘텐츠를 탐색하게 한다.
- 동작:
  - 마우스 더블클릭으로 폴더 창을 연다.
  - 키보드 focus 상태에서 Enter 또는 Space로 폴더 창을 연다.
  - 이미 열린 폴더를 다시 실행하면 해당 창을 최상위로 올린다.
- 예외:
  - 동일한 폴더 창은 중복으로 여러 개 열지 않는다.

### FEAT-005 창 관리

- 목적: 데스크톱 앱처럼 콘텐츠 창을 조작할 수 있게 한다.
- 지원 기능:
  - 열기
  - 닫기
  - 드래그 이동
  - 클릭 시 활성화
  - z-index 갱신
- MVP 보류 기능:
  - 최소화
  - 최대화
  - 창 크기 조절
- 접근성:
  - 닫기 버튼은 명확한 `aria-label`을 가진다.
  - 창 제목은 heading 또는 labelledby로 연결한다.

### FEAT-006 Dock 바로가기

- 목적: 주요 콘텐츠와 외부 링크에 빠르게 접근한다.
- 항목:
  - Home 또는 Desktop
  - About
  - Projects
  - Resume
  - Contact
  - GitHub
- 동작:
  - 내부 항목 클릭 시 해당 창을 연다.
  - 외부 항목 클릭 시 새 탭으로 이동한다.
  - 열린 창이 있는 항목에는 indicator를 표시한다.

### FEAT-007 Menu Bar

- 목적: OS 감성을 강화하고 보조 기능을 제공한다.
- 표시 요소:
  - 포트폴리오 이름
  - 현재 활성 창 이름
  - 테마 토글
  - 현재 시간
- 선택 기능:
  - 검색 버튼
  - 전체 화면 안내

### FEAT-008 프로젝트 목록과 상세

- 목적: 대표 프로젝트 3개를 깊이 있게 보여준다.
- 목록 표시:
  - 프로젝트명
  - 한 줄 요약
  - 역할
  - 핵심 기술 태그
  - 썸네일
- 상세 표시:
  - 프로젝트 한 줄 가치
  - 문제 정의
  - 내 역할
  - 기술 스택
  - 주요 구현
  - 트러블슈팅
  - 성과와 배운 점
  - GitHub, 배포 링크
  - 이미지 또는 영상

### FEAT-009 이력서 요약과 PDF 다운로드

- 목적: PDF 다운로드 전에 핵심 정보를 빠르게 확인하게 한다.
- 웹 요약본:
  - 한 줄 소개
  - 핵심 역량 3개
  - 대표 프로젝트 3개 요약
  - 기술 스택 요약
  - 교육, 활동, 수상 요약
- PDF:
  - `public/resume/resume.pdf` 경로에 배치한다.
  - 다운로드 버튼은 파일명과 형식을 명시한다.

### FEAT-010 Skills 탐색

- 목적: 기술 경험을 단순 나열이 아니라 맥락별로 보여준다.
- 카테고리:
  - Frontend
  - State Management
  - Styling
  - Tooling
  - Collaboration
  - AI Workflow
- 표시 방식:
  - 기술명
  - 숙련도 표현
  - 사용 프로젝트
  - 짧은 사용 맥락

### FEAT-011 Contact 링크

- 목적: 방문자가 빠르게 연락하거나 외부 프로필로 이동한다.
- 항목:
  - 이메일
  - GitHub
  - 블로그
- MVP에서는 서버 저장형 연락처 폼을 제공하지 않는다.

### FEAT-012 테마 전환

- 목적: 감성적인 macOS풍 UI를 light/dark 양쪽에서 유지한다.
- 동작:
  - Menu Bar 또는 Dock 인근 토글로 전환한다.
  - 사용자의 선택은 localStorage에 저장한다.
  - 첫 방문 시 system preference를 따른다.

### FEAT-013 모바일 레이아웃

- 목적: 모바일에서 데스크톱 창 조작의 불편함을 줄인다.
- 동작:
  - 잠금화면 랜딩은 유지한다.
  - 입장 후에는 폴더 카드 리스트 또는 앱 런처형 레이아웃로 표시한다.
  - 상세 콘텐츠는 전체 화면 패널로 표시한다.
- 제약:
  - 모바일에서는 창 드래그를 핵심 상호작용으로 사용하지 않는다.

### FEAT-014 접근성 탐색

- 목적: 키보드와 보조 기술 사용자도 탐색할 수 있게 한다.
- 요구:
  - 모든 폴더, Dock 항목, 버튼은 focus 가능해야 한다.
  - focus ring을 숨기지 않는다.
  - 모션 감소 설정을 지원한다.
  - 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.

### FEAT-015 SEO와 OG

- 목적: 공유와 검색에서 포트폴리오 정보를 명확하게 보여준다.
- 항목:
  - title
  - description
  - canonical URL
  - Open Graph title, description, image
  - Twitter card
  - sitemap
  - robots

### FEAT-016 정적 콘텐츠 관리

- 목적: BE 없이 콘텐츠를 관리한다.
- 방식:
  - 구조화 데이터는 TypeScript 파일로 관리한다.
  - 긴 프로젝트 상세는 MDX 또는 Markdown으로 관리한다.
  - 이미지와 PDF는 `public` 아래 정적 자산으로 관리한다.

### FEAT-017 MVP 범위 정책

- 목적: MVP가 합의된 범위를 벗어나지 않도록 콘텐츠와 라우팅 구성을 제한한다.
- 정책:
  - 블로그와 노트는 내부 핵심 폴더와 MVP 라우팅에 포함하지 않는다.
  - 외부 블로그 링크는 Contact 또는 Dock quick link로만 제공할 수 있다.
  - UI 문구와 콘텐츠 데이터는 한국어로 작성한다.
  - 서버 API, DB, 인증, CMS, 서버 저장형 연락처 폼을 구현하지 않는다.
  - 모든 MVP 콘텐츠는 정적 파일과 빌드 타임 데이터로 제공한다.
- 확인 기준:
  - Desktop 기본 폴더는 About Me, Projects, Skills, Resume, Contact로 제한된다.
  - 내부 `/notes`, `/blog` 라우트는 MVP에서 생성하지 않는다.
  - API route 또는 서버 저장 로직이 없다.

## 5. 오류와 빈 상태

- 프로젝트 링크가 없는 경우 버튼을 숨기고 텍스트로 대체한다.
- 이미지가 없는 프로젝트는 기본 썸네일을 사용한다.
- 이력서 PDF 파일이 없으면 다운로드 버튼을 비활성화하고 웹 요약본은 표시한다.
- 외부 링크는 새 탭으로 열고 `rel="noreferrer"`를 사용한다.

## 6. 완료 기준

- 모든 MVP 기능이 `REQ-` 요구사항과 연결된다.
- 잠금화면에서 데스크톱으로 진입하는 흐름이 끊기지 않는다.
- 대표 프로젝트 3개가 같은 정보 구조로 표시된다.
- 모바일에서 모든 핵심 콘텐츠에 접근 가능하다.
