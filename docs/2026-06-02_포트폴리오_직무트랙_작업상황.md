# 2026-06-02 포트폴리오 직무 트랙 작업상황

## 1. 현재 결정

루트(`/`)는 기존 OS 포트폴리오 허브로 유지한다. 특정 지원 직무에 맞춘 별도 화면은 같은 코드베이스와 같은 데이터 소스를 쓰되, URL 경로별로 헤드라인, 사례 정렬, 증거 배치를 다르게 보여주는 방식으로 구성한다.

이 구조는 콘텐츠를 복제한 별도 사이트가 아니라 단일 데이터 기반의 경로별 뷰다. 그래서 한 사례를 수정하면 각 트랙 화면이 같은 데이터를 다시 읽고, 유지보수 비용이 중복되지 않는다.

검색 노출은 루트 중심으로 둔다. 직무별 트랙 URL은 직접 전달용이므로 `noindex`와 루트 canonical을 적용해 검색엔진에 중복 페이지로 강하게 노출되지 않도록 했다.

## 2. 구현된 URL 구조

- `/`: 기존 OS형 통합 포트폴리오 허브
- `/public-digital`: 공공·디지털 서비스기획 트랙
- `/pm`: 주니어 PM / 서비스기획 / APM 트랙
- `/policy`: 공공/정책 기반 IT 기획·운영 트랙
- `/assembly`: 정책지원관 / 국회 보좌관 지원 트랙

각 트랙은 `TrackLandingPage`를 공통으로 사용하고, `trackId`에 따라 다른 메시지와 사례 순서를 렌더링한다.

## 3. 추가된 핵심 데이터

`profile` 폴더의 핵심자료 선별목록, 경력 타임라인, 직무역량 근거맵, 증빙 체크리스트를 기준으로 부산참여연대 경력을 프로젝트가 아니라 경력 케이스 데이터로 정리했다.

추가된 경력 케이스는 다음 6개다.

- 지역 거버넌스 참여 구조화
- 의회 모니터링 운영
- 행정사무감사 의제 정리
- 조례·예산·정책자료 분석
- 공무국외출장 검증
- 정책 글쓰기와 브리핑

수치가 검증되지 않은 표현은 과장하지 않고 `needs-check` 성격의 검증 메모로 분리했다. 화면에 노출되는 문구는 내부 파일 경로나 확장자를 그대로 보여주지 않는 방식으로 정리했다.

## 5. 사례 배치 기준

공공·디지털 서비스기획 트랙은 부산이음길을 첫 사례로 둔다. 공공 문제를 서비스 요구사항, 사용자 흐름, 기능 설계로 번역한 근거가 가장 직접적이기 때문이다.

PM/APM 트랙은 AEKKIM을 첫 사례로 둔다. 기획 의도, 사용자 경험, 운영 판단, 프론트엔드 구현을 연결해 보여주기 좋다.

정책 기반 IT 기획·운영 트랙은 부산참여연대의 지역 거버넌스 케이스를 첫 경력 사례로 둔다. 정책·행정 자료를 구조화하고 실행 가능한 의제로 바꾸는 경험을 먼저 보여준다.

정책지원관/국회 보좌관 트랙은 의회 모니터링 케이스를 첫 경력 사례로 둔다. 회의록, 의안, 행정사무감사, 예산·조례 자료를 읽고 정리한 경험이 직무와 가장 가깝다.

## 6. 검증 결과

2026-06-04 기준 커밋 전 최종 검증은 아래 명령으로 통과했다.

- `node --test`: 63개 테스트 통과
- `npm run lint`: ESLint 통과
- `tsc --noEmit`: TypeScript 타입 검사 통과
- `npm run build`: Next.js production build 통과

`npm run build` 결과 정적 라우트 `/`, `/public-digital`, `/pm`, `/policy`, `/assembly`, `/resume`, `/projects/[slug]`, `/robots.txt`, `/sitemap.xml` 생성이 완료됐다.

직전 로컬 스모크 테스트에서는 `/`, `/public-digital/`, `/pm/`, `/policy/`, `/assembly/`가 모두 200 응답을 반환했고, 트랙 경로에는 `noindex`와 루트 canonical이 적용되는 것을 확인했다.

Playwright 기반 반응형 QA에서는 `/public-digital/`, `/pm/`, `/policy/`, `/assembly/`를 390px 모바일과 1440px 데스크톱 뷰포트에서 확인했다. 네 경로 모두 `scrollWidth == innerWidth`였고 화면 밖으로 튀는 요소가 없었다.

## 7. 2026-06-04 완료된 작업

직무 트랙별 카드와 섹션 문구 분리를 완료했다.

- `/public-digital/`: `PublicServiceProjectCard` 적용. 공공 문제, 사용자 흐름, 요구사항 번역, 공공부문 적합성 중심으로 대표 프로젝트를 보여준다.
- `/pm/`: `PmProjectCard` 적용. 문제, PM 산출물, 협업 증거 중심으로 대표 프로젝트를 보여준다.
- `/policy/`, `/assembly/`: `CareerDocumentCard` 적용. 상황, 직무 연결, 역할, 산출물, 공개 증빙 중심의 문서형 경력 브리프로 보여준다.
- 루트(`/`)와 보조 프로젝트 영역은 기존 `ProjectCard`를 유지해 범용 허브 역할을 유지한다.
- 트랙별 섹션 헤딩과 설명을 `trackLandingModel`의 `caseSections`로 이동해 하드코딩을 제거했다.
- 경력 케이스 증빙에 공개 링크를 연결했다. 회의록, 오마이뉴스, 파이낸셜뉴스, 다음/쿠키뉴스 링크가 카드의 공개 증빙 영역에 노출된다.
- 카드와 섹션의 모바일 폭 안정화를 위해 `min-w-0`, `max-w-full`, `break-words`, 모바일 1열 그리드, CTA 줄바꿈 처리를 추가했다.
- 계약 테스트를 보강해 공개 증빙 링크와 트랙별 카드/섹션 문구가 유지되도록 했다.
