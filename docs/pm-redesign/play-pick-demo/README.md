# Play Pick 온보딩 시연

2026-09-11에 원본 온보딩 UI를 별도 로컬 환경에서 실행하여 촬영했습니다.

## 저장한 파일

- `play-pick-onboarding.mp4`: 보관용 영상. 1280×960, 24fps, 약 30.6초, 음성 없음.
- `onboarding-start.png`: 온보딩 시작 화면.
- `first-recommendations.png`: 완료 후 첫 추천 목록.
- `capture-manifest.json`: 촬영 방식, 사용한 데이터, 대기 구간 편집, 파일 해시.
- `verification.json`: 별도 시연 계정의 실제 저장 결과 확인.
- 사이트용 영상: `public/pm/previews/play-pick.mp4` (960×720, 약 0.87MB).
- 사이트용 포스터: `public/pm/previews/play-pick.webp`.

## 영상에 담은 흐름

호불호 선택 전 상태 → 보고싶어요 → 모르겠어요(완료 개수 유지) → 안볼래요 → 호불호 총 8개 → 완료 → 환영 화면 → 홈의 첫 추천 목록.

브라우저의 실제 화면을 연속 캡처하고 촬영 시각에 맞춰 MP4로 인코딩했습니다. 원본 CSS의 카드 전환과 진행률, 환영 화면을 촬영했으며 새 화면 전환을 합성하지 않았습니다. 촬영 조작 사이의 대기 구간 약 12.3초를 제거했습니다. 첫 번째 구도 점검 촬영은 포스터 상단이 잘려 제외하고, 전체 카드와 버튼이 보이는 1600×1200 화면으로 다시 촬영했습니다.

## 원본과 실행 환경

- 원본 프로젝트: `SSAFY/프로젝트/1. 관통pjt/final-pjt`.
- 프런트엔드: Git `c5e2f13`에 저장된 `front/`를 작업 폴더 내부에 별도 추출하여 빌드했습니다. 2026-09-09에 수정한 온보딩 화면을 원본 화면으로 덮어쓰지 않았습니다.
- 백엔드: 현재 로컬 Django 코드를 사용했습니다. API 응답을 모킹하지 않았습니다.
- 데이터: 2026-09-09 공개 KOPIS 스냅샷과 기존 DB에 보관된 공연 임베딩 3,088개를 **별도 SQLite DB**에 복사했습니다. 원본 DB의 사용자·게시글 등 개인 데이터는 복사하지 않았습니다.
- 시연 계정과 선택은 예시입니다. 원본 계정·DB·소스에 녹화용 변경을 적용하지 않았습니다.
- 외부 AI API를 호출하거나 새 임베딩을 생성하지 않았습니다. 공연 포스터는 원본 공개 이미지 URL을 사용합니다.
- 개인화 추천은 취향·지역·인기 등 여러 기준을 결합한 결과입니다. 영상에서 표시되는 추천 사유는 지역 정보이며, 온보딩 선택만으로 추천 순위가 달라졌다는 실험은 아닙니다.
- 녹화 범위는 온보딩과 첫 추천입니다. YouTube·지도·자연어 검색 등 다른 외부 연동의 정상 동작을 검증한 영상은 아닙니다.

## 확인

- 예시 계정의 온보딩 완료 상태와 호불호 신호 8개 저장 확인.
- 1,536차원 선호 벡터 생성 및 L2 norm 약 1 확인.
- UI에서 호불호 8개 이전 완료 버튼 비활성화, 중립 선택 후 개수 유지 확인.
- 추천 목록과 추천 사유 노출 확인.
- 보관용·사이트용 MP4 전체 디코딩 통과.

이 시연은 기능 연결을 보여주는 자료입니다. 추천 정확도, 온보딩 완료율, 사용자 만족도 등의 성과 지표는 측정하지 않았습니다. 당시 명세와 개인 기여 근거는 `public/pm/sources/play-pick-onboarding.txt`, `play-pick-implementation.txt`에 별도 발췌했습니다.

원시 프레임·촬영 시각·별도 DB·실행 스크립트는 Git에서 제외한 `.codex_tmp/playpick-capture/`에 보관합니다. `take2/`, `take2.json`, `encode.py`가 최종 영상의 원본이며, `original/front/`는 원본 프런트엔드 복사본입니다. `node_modules`는 기존 의존성을 읽기 위한 연결이므로 이 작업 폴더를 통째로 재귀 삭제하지 마세요.
